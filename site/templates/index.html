Nothing moves at run time

  1. Weights are copied as stored. The one interim cast is named on the model pages.
  2. Experts are placed once from the VRAM budget, and the placement is part of the checked-in profile.
  3. Every choice that affects speed or output is resolved once per model, never keyed on a model's name.
  4. An expert that moves between the card and RAM changes speed, never text.
  5. A regression past the paired interval, or past run-to-run speed, fails the release.

The build refuses any compute capability except {{ v('machine.gpu.compute_cap') }}. On another Ada card it builds, and every number has to be measured again.

The boundary

The one number the engine publishes as its quality claim: the distance between its next-token distribution and the full-precision model's, on the same text.

KLD measures how much one probability distribution differs from another. Zero means identical. The gate scores the target token's log-probability at every scored position of a wikitext chunk against a frozen base, then reports the mean over {{ m.num('sparse.quality.rows') }} rows. Lower is closer. The base is the model's {{ v('machine.formats.bf16') }} file: the unquantized reference this repository calls full precision.

The engine does not claim the distance is zero. It claims the distance is measured, paired per chunk, and small enough that the gate can separate the cache formats it has to choose between.

{{ m.chart(charts.boundary_sparse) }}

The chart is the overlap the repository's rows file can support: the base's probability of the ground-truth next token and the engine's at every scored position of one chunk. It is not a full-vocabulary overlap. The rows file stores the target token's log-probability, not the top-k distribution; a full overlap would need the twelve-gigabyte base file, which is not in the repository.
