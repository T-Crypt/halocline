# Build BF16-quality sm_89 sparse-dense engine

> **Audit note (2026-11-16):** this report was reviewed against primary sources after generation. Four corrections were applied: (1) the sparse target is **Qwen3.8-Flash-Next (`qwen4_exp`), the model basalt's `qwen4exp` adapter implements**, not Qwen3-Next-80B (which is only an architecture analogue); both model configs were verified from HF `config.json`; (2) KV cosine-vs-FP32 figures were corrected to int8 99.8% / rk8v4 99.4% / rk4v4-e8 98.7% / rk4v4 97.8% / rk2v4-e8 96.2% (the earlier prep docs had mislabeled 99.8% as rk4v4-e8); (3) PolyStrata facts were verified from its repo; (4) "KLE" is normalized to KLD (KL divergence) on next-token logits; (5) Qwen4 family forward-compat added — Qwen4-Max is closed-weight/API-only, but its GDN+QSA+gated-residual+n-gram architecture is what Flash-Next (`qwen4_exp`) previewed, so the component/config-driven adapter design targets the future open Qwen4 models too. See [`BUILD_SPEC.md`](../design/BUILD_SPEC.md) for the aligned, build-ready decisions and [`AUDIT_LOG.md`](../design/AUDIT_LOG.md) for the full correction record.

The build-out of an sm_89-native CUDA/C++ engine for sparse and dense models must treat BF16 as the quality reference and preserve quality as a system property across recurrent state, attention, KV cache, offload, quantization, and speculative decoding, because kernel-level numeric choices compound across 64-layer hybrid schedules and 512-expert MoE routing. The available evidence — NInfer sm_89 ports, Basalt local records, vLLM/SGLang documentation, and the GDN/linear-attention literature — shows that no single threshold defines a "match," so a defensible claim requires multi-layer validation: KLD/PPL/top-1/logit-hash gates, greedy identity, seeded-sampling reproducibility, and task/long-context canaries. Speed and greedy throughput are secondary to these invariants, and several optimizations (NVFP4 KV, FlashInfer GDN kernels, cluster barriers) are simply unavailable or unsafe on Ada and must be gated out rather than emulated.

## Dense GDN hybrids and sparse MoE targets set the architecture

The primary dense reference is Qwen3.8-27B (`model_type: qwen3_5`, `Qwen3_5ForConditionalGeneration`): 64 transformer blocks arranged as 16 repeats of three Gated DeltaNet (linear-attention) layers followed by one full gated-attention layer (48 GDN + 16 full attention), hidden 5120, FFN 17408, GDN geometry 48 value heads / 16 query-key heads at head dim 128 with conv kernel 4 and `mamba_ssm_dtype: float32`, full attention at 24 query / 4 KV heads at head dim 256, `attn_output_gate: true` with `output_gate_type: swish`, partial RoPE factor 0.25, MRoPE interleaved with sections [11,11,10], rope theta 10,000,000, MTP with one hidden layer sharing embeddings, 262,144 max positions, and a ViT vision tower (depth 27, hidden 1152, patch 16, merge 2) ([Qwen/Qwen3.8-27B config.json](https://huggingface.co/Qwen/Qwen3.8-27B/raw/main/config.json), verified 2026-11-16). Dense-hybrid means dense FFN weights with a hybrid attention mechanism, so expert routing is not a concern but recurrent-state fidelity, KV behavior, and mixed-layer scheduling are first-order correctness issues. The sparse reference target for this project is **Qwen3.8-Flash-Next (`qwen4_exp`, `Qwen4ExpForConditionalGeneration`) — the model basalt's `qwen4exp` adapter actually implements** — not the 80B Qwen3-Next family. Its verified config is: 48 layers (36 GDN linear-attention + 12 full-attention at `full_attention_interval: 4`), hidden 2560, 512 experts with 10 active + 1 shared expert (`moe_intermediate_size: 640`), GDN 48 value / 16 query-key heads at head dim 128 with conv kernel 4 and float32 SSM state, full attention at 24 query / 2 KV heads at head dim 256 with `output_gate_type: sigmoid`, QSA sparse attention (`indexer_budget: 2048`, `indexer_compress_ratio: 4`), gated residual (`hc_count: 4`, `hc_lowrank: 320`), a 51B-parameter n-gram/PLE embedding at layer 2 (`ngram_size: 3`, `ngram_vocab_size_base: 20000000`), one MTP layer (`mtp.hybrid`, QSA attention), 262,144 max positions, and ViT vision ([Qwen/Qwen3.8-Flash-Next config.json](https://huggingface.co/Qwen/Qwen3.8-Flash-Next/raw/main/config.json), verified 2026-11-16; `~/wt/basalt-ada-lift/src/models/qwen4exp`). Qwen3-Next-80B-A3B / Qwen3-Coder-Next (80B total, 3B active, 512 experts top-10 + 1 shared) remain useful *architecture analogues* but are not the adapter target. For both families, BF16-quality execution means matching layer schedule, head geometry, positional encoding, state semantics, PLE/QSA behavior, and MTP behavior rather than treating them as standard Transformers; the GDN state must be preserved across all execution paths including speculative rollback.

## sm_89 kernels need FP32 accumulation and arch-gated primitives

Ada (sm_89) exposes warp-level MMA tensor-core instructions including FP16/BF16 m16n8k16-class and FP8 e4m3/e5m2 m16n8k32 forms, plus INT8 MMA, but numerical quality versus BF16 depends less on the MMA mnemonic than on input format, accumulation precision, scaling/dequantization, and reduction order ([NVIDIA PTX ISA: Warp Level Matrix Instructions](https://docs.nvidia.com/cuda/parallel-thread-execution/#warp-level-matrix-instructions-mma)). The NInfer sm_89 port record establishes that FP32 accumulation is half-rate on Ada for the plain fp8 mma path and that upstream block-scale fp8 mma was unit-scale (UE8M0) only for Blackwell full-rate accumulation, with the plain sm_89 fp8 mma numerically identical in that context — a pressure to trade throughput for accumulation precision that must be resisted in quality-critical kernels (`~/<private>/reference/records/ninfer-v3-port.md`). Architecture gating is mandatory: TMA, cluster-scope barriers, `mbarrier.try_wait` suspend, `fence.mbarrier_init.release.cluster`, and PDL device intrinsics are sm_90+ and must stay compile/runtime-gated, with TMA paths replaced by `cp.async` pipelines and cooperative occupancy computed via `cudaOccupancyMaxActiveBlocksPerMultiprocessor` rather than static constants that overflow Ada (`~/<private>/reference/records/ninfer-v3-port.md`). The dominant numeric pitfalls are FP16 intermediate overflow versus BF16 dynamic range in epilogues, FP16 accumulators in GEMM/softmax paths, non-deterministic atomic reductions in sparse gathers/scatters, differing reduction tree shapes between prefill and decode kernels, and fused epilogue reordering that changes rounding points. Even high-precision baselines drift measurably: BF16 versus FP16 shows mean KLD 2.515e-5 and RMS delta-p 0.15% on LLaMA 3 8B ([llama.cpp perplexity README](https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/perplexity/README.md)), and NInfer's gdn gating rel_l2 measured 1.434e-6 versus an upstream 1.4e-6 limit — requalified to 2.0e-6 on sm_89 — proving small arch-dependent deltas are real and tolerances must be measured rather than copied from sm_120a oracles.

## GDN recurrent state dominates dense quality

GDN quality is dominated by recurrent-state fidelity: decay (alpha), delta update (beta), key/query L2 normalization, causal depthwise convolution with kernel 4, and output gating all interact over long horizons, and Qwen3.5's config explicitly sets `mamba_ssm_dtype: float32`, `linear_conv_kernel_dim: 4`, and `attn_output_gate: true` ([Qwen/Qwen3.5-27B config.json](https://huggingface.co/Qwen/Qwen3.5-27B/raw/main/config.json)). On sm_89, BF16 model weights are not sufficient if recurrent state S, conv intermediates, or gate math are aggressively quantized or accumulated poorly; the state and gate-sensitive accumulations must stay in FP32, with the conv boundary handling, padding/cache warmup, SiLU placement, alpha/beta parameterization, clamping, and the `rms_norm(output) * silu(z)` output-gate fusion all matched to reference semantics ([Gated Delta Networks: Improving Mamba2 with Delta Rule](https://arxiv.org/html/2412.06464v1), [Gated DeltaNet for Linear Attention (LLMs-from-scratch)](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch04/08_deltanet/README.md)). ReplaySSM checkpoint-plus-recent-input-buffer state management affects both throughput and correctness under speculative decoding and chunked serving, and NInfer's sm_89 ports advertise ReplaySSM state transactions as part of the Qwen3.8 runtime — state transaction correctness is as important as raw kernel speed on Ada where Hopper-targeted GDN kernels are unavailable ([ReplaySSM: Rethinking State Storage for Faster Hybrid-Model Decoding](https://developer.nvidia.com/blog/replayssm-rethinking-state-storage-for-faster-hybrid-model-decoding/), [sergiuszm/ninfer-4090](https://github.com/sergiuszm/ninfer-4090)). Practical sm_89 baseline is Triton/FLA or custom fused kernels, since FlashInfer GDN support centers on SM90/SM100/SM103 ([SGLang Attention Backend](https://docs.sglang.io/docs/advanced_features/attention_backend), [FlashInfer issue #1690](https://github.com/flashinfer-ai/flashinfer/issues/1690)).

## KV cache and context quality trade capacity against BF16 fidelity

On a 24 GB Ada card, format choice is a quality-versus-resident-context trade: BF16/INT8 maximize precision headroom but cap context, while rotated/E8-compressed modes recover the native 256K+ envelope at measured quality cost. NInfer-4090 documents KV storage options `bf16|int8|fp8|nvfp4|k8v4|rk8v4|rk4v4|rk4v4-e8|rk2v4-e8` but states `nvfp4` and `k8v4` are upstream sm_120a modes unavailable on RTX 4090 in the fork, with `rk4v4-e8` recommended for long context (`~/wt/ninfer-v3/docs/cli.md`). Measured results show INT8 closest to the high-precision baseline with cosine 99.8% versus FP32, `rk4v4-e8` at 98.7% cosine with exact single-needle, 5-needle, and code-detail retrieval through 260K and MTP acceptance 78.8% versus INT8 78.4%, and `rk2v4-e8` at 96.2% cosine passing retrieval gates at 260K with ~10% decode tax (`~/wt/ninfer-v3/README.md`, [UDPSendToFailed/ninfer-4090 README](https://raw.githubusercontent.com/UDPSendToFailed/ninfer-4090/feat/rtx-4090-sm89-native/README.md)). E8 compression encodes 256-d keys as 8-d subspaces that are Hadamard-rotated, normalized/scaled, and projected via Conway-Sloane E8 nearest-lattice search (D8 union D8+0.5) with a residual E8 stage, inverse-rotated and reconstructed, evaluated by cosine and multi-needle retrieval in a synthetic oracle asserting mean cosine >= 0.990 and 100% needle retrieval (`~/wt/ninfer-v3/tools/test_kv/kv_oracle.py`). YaRN (arXiv:2309.00071) extends RoPE by rescaling/interpolating rotary frequencies with attention-temperature scaling, enabling 1M envelopes in ninfer-4090 forks, but a 1M envelope does not imply uniform quality at 1M and must be validated with depth-sensitive probes ([YaRN: Efficient Context Window Extension](https://arxiv.org/abs/2309.00071)). Full-attention layers (16 of 64) use GQA (24 Q / 4 KV, head dim 256), attention output gating, and partial/MRoPE positional settings; because only one in four layers is full attention, attention-kernel quality issues can be masked in short prompts but dominate retrieval and localization tasks. KV-cache dtype and layout are quality knobs on these layers, and errors in RoPE application (partial factor, MRoPE sectioning/interleaving) appear as long-context or position-sensitive regressions rather than crashes.

## Memory, offload, and serving preserve quality only with byte-correct residency

On Ada hosts, host RAM pressure threatens availability and correctness more than steady-state numeric quality when BF16 compute and KV are preserved: Strata pages/locks ~20.9-21 GiB of host RAM for experts and leaves ~10 GiB on a 31 GB box, and a parallel CUDA build at high concurrency beside a resident Strata OOM-froze the machine (`~/<private>/guide/strata-and-ninfer.md`). NInfer exposes `memory_headroom` (default 512 MiB, deducted per rank) and `context_capacity` as startup/planning controls, and vLLM sizes KV cache against measured free memory with preemption/recompute as the default pressure response (`~/wt/ninfer-qwen4/ninfer.example.toml`, [vLLM Optimization and Tuning](https://docs.vllm.ai/en/stable/configuration/optimization.html)). For BF16-reference serving, prefer exact tiering — BF16 weights/KV/state copied unchanged or recomputed from exact token history — over quantized/offloaded KV formats, and require strong identity/invalidation semantics, checksums/versioning where possible, and no silent reuse of stale blocks at tier boundaries. Tiered MoE architectures (Basalt explicit VRAM slot caches plus RAM/file/peer tiers, Strata pinned-RAM plus file-backed expert streaming, KTransformers GPU-CPU-disk prefix cache) preserve quality when tier transitions copy exact expert bytes, execution uses numerically equivalent kernels for hit/miss paths, and aggregation dtype/order is unchanged; the highest-risk bug is a residency map pointing to a slot containing a different expert, which produces coherent-looking but wrong outputs, mitigated by byte-for-byte `verify_slot` comparison, synchronized swap windows, and explicit spill counters (`~/wt/basalt-upstream-lift/include/basalt/core/expert_cache.hpp`, `~/wt/basalt-upstream-lift/include/basalt/core/expert_source.hpp`). Under concurrency, quality-preserving serving requires deterministic scheduling modes where supported, bounded batch/token budgets, and cache policies with explicit correctness contracts; SGLang documents that floating-point non-associativity and varying batch composition cause nondeterminism even at temperature 0, and provides deterministic inference mode with backend constraints ([SGLang Deterministic Inference](https://docs.sglang.io/advanced_features/deterministic_inference.html)). KV-cache corruption risk concentrates at offload copies, eviction/reuse, paging/block tables, async handoff, and restart/resume boundaries, so strong request/sequence IDs, generation counters, and cache invalidation on engine restart are essential.

## Quantization, artifacts, and speculative decoding require validation before trust

For GGUF-style local inference, K-quants and I-quants dominate low-bit weight formats, with `Q8_0` commonly treated as near-lossless, `Q6_K`/`Q5_K_M`/`Q4_K_M` close when calibrated, and `IQ4_XS` retaining strong quality only with imatrix calibration (VisionPsy-Nano reports -1.49% normalized versus FP32 baseline for IQ4_XS with imatrix versus -4.62% for legacy Q4_0) ([VisionPsy-Nano-460M-GGUFs](https://huggingface.co/qvac/VisionPsy-Nano-460M-GGUFs), [llama.cpp quantize README](https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/quantize/README.md)). An imatrix is calibration-derived activation/importance statistics used by `llama-quantize` to allocate quantization error toward less important weights, and should be default for quality-first 4-5 bit builds with representative calibration data and reviewed output/embedding handling ([llama.cpp imatrix README](https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/imatrix/README.md)). Layer-/tensor-specific mixed precision (embeddings/lm_head and sensitive tensors at higher precision, bulk FFN more aggressively) often improves quality-per-byte versus uniform low-bit, and `llama-quantize` supports per-tensor overrides via `--tensor-type` ([llama.cpp quantize README](https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/quantize/README.md)). NVFP4/MXFP4 target Blackwell (compute capability 10.0) per current scheme tables and should not be assumed as primary quality-preserving paths on sm_89 ([llm-compressor Choosing the right compression scheme](https://github.com/vllm-project/llm-compressor/blob/main/docs/steps/choosing-scheme.md)). On Ada, FP8 W8A8 is first-class in vLLM/llm-compressor and LMDeploy (compute capability >= 8.9) ([vLLM FP8 W8A8 docs](https://docs.vllm.ai/en/latest/features/quantization/fp8.html), [LMDeploy W8A8](https://github.com/InternLM/lmdeploy/blob/main/docs/en/quantization/w8a8.md)). Artifact formats: `safetensors` is the canonical BF16 reference, `GGUF` the most inspectable quantized path, while `.ninfer` and `.basalt` are engine-specific and lack public specs — quality claims require converter/probe/dequant parity tooling (`~/<private>/projects/active/basalt-ada-engine/project.md`, `~/<private>/projects/active/basalt-ada-engine/RESEARCH_PREP.md`). Low-bit quantization systematically shrinks decision margins and can flip discrete decisions (tool-use gating, refusals, structured choice) even when aggregate metrics look acceptable, so decision-sensitive tasks must complement PPL/KLD ([arXiv:2608.06564](https://arxiv.org/abs/2608.06564)). Speculative decoding (MTP, DFlash, DSpark, n-gram) is lossless when the target model verifies via rejection sampling over the same target logits/distribution as non-speculative BF16 decoding; approximate/lossy behavior arises only from non-standard verifiers such as vLLM FLy, omitted verification, or evaluation regimes that change sampling settings ([vLLM speculative decoding README](https://raw.githubusercontent.com/vllm-project/vllm/main/docs/features/speculative_decoding/README.md), [DFlash: Block Diffusion for Flash Speculative Decoding](https://arxiv.org/html/2602.06036)). Acceptance is highly workload-dependent: NInfer-4090 reports MTP7 at 100% draft acceptance (8.00 tok/round) on deep-context greedy runs, 88.0% (7.11 tok/round) on prompt-cached runs, and 28.4% on cold-corpus runs ([UDPSendToFailed/ninfer-4090 README](https://raw.githubusercontent.com/UDPSendToFailed/ninfer-4090/feat/rtx-4090-sm89-native/README.md)); DFlash reports over 6x lossless acceleration with average acceptance length ~6.5; DSpark uses confidence-driven variable verify length ([DSpark in SGLang](https://lmsys.org/blog/2026-07-06-dspark-sglang/)). On 24 GB Ada, BF16 target plus long context plus speculative drafter/KV/workspace is tight, so quality-focused configs must budget headroom before increasing draft window or tree depth, and MTP may require almost no extra model memory when heads are in-checkpoint while DFlash/DSpark need companion draft weights ([Jetson Speculative Decoding tutorial](https://www.jetson-ai-lab.com/tutorials/speculative-decoding)).

## Validation must be multi-layered because no single metric suffices

A defensible BF16-quality claim on sm_89 requires layered evidence with fixed configs and paired comparisons: determinism checks, distribution/logprob gates versus BF16 reference, greedy identity/top-1 parity, seeded-sampling reproducibility, and no-regression task/long-context canaries with uncertainty reporting. Basalt's decode-path gate scores wikitext-2 in 512-token chunks with first 256 prefilled, rows 256-510 scored through decode in verify windows, KLD as `KL(base || test)` over the full vocabulary from fp32 log-softmax summed in double with base terms at log-probability <= -16 skipped, reporting PPL, mean/median/p99 KLD, and top-1 agreement; 20 chunks for quick checks, 100 for numerics changes, with bitwise-neutral changes required to show greedy identity (`~/wt/basalt-ada-lift/docs/precision/quality.md`). Infernix/ninfer-style tooling compares next-token distributions position-by-position with mean KLD `KL(reference || engine)`, 99.9th percentile KLD for tail positions, top-1 agreement, and PPL versus reference as percent change, warning that chunk/order changes can create ~1% PPL noise and KL ~0.025-0.033 on 4-bit-activation artifacts and recommending means over >=5-6 chunk sizes paired by chunk size ([Infernix quality docs](https://github.com/Wallawalla47/Infernix/blob/main/docs/quality.md)). The critical caution is that PPL/KLD can fail to rank near-baseline variants: "Displacement Is Not Direction" finds non-significant KLD-quality correlations in the >=99% BF16-quality silent zone, and "Which Decisions Low-Bit Quantization Breaks" shows aggregate scores can stay flat while specific decisions flip, so tolerances must be empirical and task-aware with paired comparisons, tail metrics, and task-specific canaries rather than a single universal KLD cutoff ([arXiv:2606.19558](https://arxiv.org/html/2606.19558), [arXiv:2608.06564](https://arxiv.org/abs/2608.06564)). Determinism must be tested at the right layer: same binary/GPU/config yields repeatable outputs, but batch size, prefix/cache state, chunk/prefill size, and kernel path can change results, and atomics in specific kernels are genuine nondeterminism sources ([arXiv:2606.00279](https://arxiv.org/abs/2606.00279)). Standard suites span WikiText-2 PPL/KLD, MMLU/MMLU-Pro/GPQA/AIME/GSM8K, HumanEval/MBPP, and NIAH/RULER for long-context retrieval, with EvalScope/lm-evaluation-harness for reproducible task evals and metadata completeness (hardware, KV dtype, speculative settings, seeds, repeats, failed/truncated counts) as part of auditable methodology ([lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness), [EvalScope](https://github.com/modelscope/evalscope), [RULER](https://arxiv.org/abs/2404.06654)). For speculative decoding specifically, validate greedy equivalence and stochastic distribution parity versus non-spec BF16 across batch sizes and long-context lengths, segment acceptance by cache hit/cold, context length, draft depth, and KV mode, and use cap-accept-style observability to distinguish good trims from lossy ones ([vLLM speculative decoding README](https://raw.githubusercontent.com/vllm-project/vllm/main/docs/features/speculative_decoding/README.md), [DSpark in SGLang](https://lmsys.org/blog/2026-07-06-dspark-sglang/)). Long-context validation must include NIAH/RULER multi-needle and code-detail probes at multiple depths and after cache eviction/swap events, because KV and expert tiering interact under memory pressure. Reports must include exact hardware/driver/CUDA, engine commit/build flags, tokenizer/chat template, batch/chunk/graph settings, KV/cache settings, and all generation/eval seeds/params to make match claims falsifiable.

## Conclusion

The central implication is that BF16 quality on sm_89 is a property of the whole execution system — recurrent state precision, attention/RoPE exactness, KV quantization policy, offload residency correctness, quantization recipe, and verification semantics — rather than of any single kernel, so the engine's architecture must make each of these independently measurable and gateable before speed work proceeds. The strongest available evidence is implementation-centric (NInfer sm_89 ports, Basalt local records, Strata operational measurements) rather than standardized benchmark literature, which means the project should define its own BF16 reference, calibration corpora, and acceptance bands from measured baselines on the target hardware and treat published thresholds as starting points rather than contracts. The most productive next steps are: pin a BF16 reference path with FP32 GDN state and exact attention/RoPE; implement arch-gated sm_89 kernels with FP32 accumulation; choose KV mode per workload with NIAH validation; require imatrix and mixed precision for any sub-8-bit artifact; gate every speculative path on target verification with segmented acceptance telemetry; and build the multi-layer validation suite (distribution gates, greedy identity, seeded sampling, task canaries, long-context probes, pressure/recovery tests) as a first-class deliverable rather than an afterthought.
